# Deviations from CONFIRM_PREREG.md

1. **Planning-horizon padding (engineering fix, before any confirmatory result was read).** The first launch (seed 10) stopped with "horizon too short" at f = 3.0, T = 12 h: intermediate CA-List attempts inside deadline repair can place tasks beyond the 47-h issued forecast before the attempt is rejected. Fix: the scheduler horizon is D + T and the planning CI is padded beyond the last forecast window with that window's value. Valid plans never use the padded values (all tasks finish by D <= 36 h; candidate starts are bounded by LST <= D and local-search moves by D - d). The partial output of the failed launch was deleted without being read. Re-verified on development data (pilot months) for all 10 workflows at T = 12 h.
2. **Execution split by seed.** The study is run as five processes (one per seed) because a single background process is limited to 2 h. Submission draws depend only on the seed, so the split reproduces the single-run design exactly. Outputs `results/confirm_s<seed>.csv` are concatenated before analysis.
3. **Documentation correction, CaWoSched adapter (found after the confirmatory run; code unchanged).** The adapter's docstring said its CI-to-budget mapping "follows CWM". In fact it maps CI into the full range [0, P x work power], while CWM uses [P_min, P_min + 0.2 or 0.4 x dynamic power]. The code that produced the confirmatory results is unchanged; only the description was wrong. A development-data check (EXTENSION_NOTES.md section 1) shows the full range gives CaWoSched its best oracle saving (4.85% vs 2.34-2.56%), so the reported CaWoSched results are not handicapped. The paper's methods section states the mapping actually used.
